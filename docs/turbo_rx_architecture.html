Turbo RX — the Canon Demodulator Streaming, superframe-aware decode for the NBFM image modem · architecture, algorithms & channel-sim benchmarks · 2026-06-23

Scope. This documents the turbo receive path — the streaming, superframe-aware V3Session decoder and its per-segment canon demodulator (reequalise_span_joint + canon_demod_segment) — as opposed to the OTA-validated rx_v2 batch decoder (the "legacy" path, the source of truth, left untouched). The turbo path is the development/quality path, gated on at the worker level (turbo = true). Branch feat/v3-turbo.

1. Pipeline structure

The turbo RX consumes 48 kHz audio in ~20 ms chunks and tracks the transmitter's superframe cadence continuously. The transmit frame is V4 (headerless): a passband preamble, a bootstrap marker carrying profile_index, an LMS warmup, and a meta codeword, followed by data segments (marker → 2 codewords + pilots). The whole PRE+marker+warmup+meta block is re-inserted every V3_PREAMBLE_PERIOD_S = 4 s as a fresh sliding-window anchor — one superframe (SF).

Marker validation decodes the marker (Golay/CRC) from the equalised out_buf; this is why the canon demodulator must never let a corrupted segment poison the live equaliser (§2). The batch rx_v2 path is structurally different (it owns the whole buffer and re-scans overlapping windows); the turbo path achieves the same coverage by re-equalising the already-buffered superframe.

2. The canon demodulator

2.1 The problem it solves — the frame mismatch

Turbo equalization (Tüchler/Koetter/Singer 2002) exchanges soft information between a SISO equaliser and a SISO decoder. The earlier soft path fed the LDPC's soft symbols E[a] back to the FFE, but those references live in the post-derotation (constellation) frame, while the raw FFE output lives in the pre-derotation (channel) frame. Adapting FFE taps on e = E[a] − y across that mismatch corrupts the equaliser. The canon demodulator removes the phase/gain inside the feedback loop so the error and the references share a frame.

2.2 One in-place joint FBF

StreamingFfe::reequalise_span_joint runs a single forward-backward-forward (FBF) NLMS over a segment, adapting the single live tap set in place (no clone — the FIR delay line is shared live state). Two cascaded estimators are folded into the loop:

  • Coarse per-group gain g_k — a least-squares fit of the known pilots per contiguous pilot run, interpolated across the span (3-point smoothed), mirroring rx_v2::track_segment's pilot-interpolation.
  • Intra-group residual phase θ_k — a bidirectional two-filter smoother (§2.3).

The joint derotation is A = (1/g_k)·e−jθ_k, so yrot = A·y is in the constellation frame. Crucially, the FFE tap update targets the FFE frame — e_ffe = e_rot / A (equivalently d·g_k·ejθ_k − y), a standard NLMS step. The naïve alternative e·conj(A) scales the step by 1/|g|² and blows up on a fade; the FFE-frame target stays well-scaled.

2.3 Bidirectional two-filter phase smoother (RTS)

Hard-won correctness note. A first attempt threaded one (θ, ν) 2nd-order DD-PLL state through the three FBF legs. It diverged (σ²≈1) via three coupled bugs: the NCO coast ran outside the confidence gate; the frequency integrator ν was never reset and accumulated across all three legs; and the backward leg flipped the coast sign (−ν) but not the integrator update, giving positive feedback. The fix is the literature-correct object.

The phase is estimated by two independent reset DD-PLL passes — a forward pass over the span (→ θ_fwd[k]) and a time-reversed pass (→ θ_bwd[k], with both the NCO coast and the frequency-integrator sign reversed) — averaged to a fixed smoothed θ[k] = ½(θ_fwd + θ_bwd). Each pass is the OTA-validated DdPll recursion (coast coupled to the gated update, β = α²/4 critically damped). No state is threaded across legs, so there is no runaway. This is the forward-backward / two-filter smoother (RTS family). It is on by default (V3_NO_TURBO_PLL disables it; with pll_alpha = 0 the path is byte-identical to gain-only).

2.4 Que du soft — strong anchors, no hard path

The loop adapts on strong confidence at the known anchors and only nudges on data:

  • Pilots: weight w = 1 (known symbols — strong anchors).
  • Data: w = |E[a]|² / (|E[a]|² + Var[a]) — uncertain symbols barely move the taps or the PLL.
  • On iteration 0 (no a-priori yet) data weight is 0 → only the anchors adapt.

There is no hard-decision path: an uncertain (or QRM/noise) symbol can never pull the equaliser like a known anchor, so a corrupted segment yields E[a]≈0 → w≈0 and cannot poison the live taps that drive the marker-validation out_buf. The |e|<|d| gate is retained.

2.5 Per-symbol noise variance σ²(t)

A single segment-average pilot σ² assigns the few faded symbols over-confident, wrong LLRs that poison the LDPC. Instead, reequalise_span_joint returns a per-symbol σ²(t): the mean pilot residual |out − ref|² per contiguous pilot run, placed at the run centre, 3-point-smoothed and interpolated across the span. The demapper (soft_demod::llr_maxlog_per_sym) scales each symbol's LLR by its local σ², so a faded symbol gets near-erasure LLRs the decoder can outvote rather than confident garbage. This recovered the last deep-fade codeword on the HIGH+ capture (111 → 112). On by default (V3_NO_PERSYM_SIGMA2 for A/B). It is the literature-standard per-symbol-reliability LLR weighting.

2.6 The SISO loop

canon_demod_segment(seg, n_cw):
  taps = live FFE taps (adapted in place)
  for it in 0..max_iter (default 5):
      refs/weights ← pilots(w=1) + data E[a] (w=reliability; 0 at it 0)
      (out, σ²(t)) = reequalise_span_joint(seg, refs, weights, is_pilot, …)   # ONE FBF
      for each codeword:
          llr  = llr_maxlog_per_sym(cw_syms, constellation, σ²(t))
          llr  = deinterleave(llr)
          (bits, extrinsic, converged) = decoder.decode_soft(llr, apriori=None, damp=0.7)
          lock converged result (best-wins)
          E[a],Var = soft_symbols_from_posterior_llr(interleave(extrinsic))
      if all codewords converged: break          # ≥1 full FBF always

The extrinsic LLRs feed the FFE (soft ISI/phase refinement), not yet the demapper as a-priori — i.e. this is the equaliser half of turbo equalization; the demapper-side a-priori loop (BICM-ID) is a documented future lever (§7). retry_failed_segments collapses to a thin re-run of this same loop once the superframe is fully buffered (taps further adapted), replacing the old hard/soft two-path retry.

3. FFE bootstrap & training

The canon demodulator never bootstraps the FFE from scratch — it inherits trained taps and only refines them. Training happens in three upstream layers:

  1. LS install on the preamble (train_lms_at, at entry acquisition and at every 4 s re-anchor): calibrate_delay finds the matched-filter peak delay (ML timing); train_ls_ridge fits the n_taps taps over the 256 known preamble symbols + LMS warmup (hugely over-determined).
  2. DD-LMS refinement over the cycle (the pure T/2 LS init is ill-conditioned alone).
  3. Continuous forward DD-LMS in push_raw — adapts the live taps on every emitted symbol's decision, error-gated (|e|<|d|), between anchors.

4. Robustness layers (unchanged from the validated path)

  • Flywheel coast — on a missed marker, blind-decode at the predicted position with reconstructed base_esi; a converged CW re-confirms sync. Noise never converges, so it cannot poison. (V3_NO_FLYWHEEL to disable.)
  • Coarse-drift estimate + rewind — try_apply_coarse_drift / estimate_drift_gardner commit a clock-drift ppm and replay from the entry preamble over the full 30 s history (replay_from_anchor), not the crippled internal buffer.
  • Backward late-entry recovery — on re-acquisition past a gap, a RewindRequest replays from the remembered SF-boundary preamble and the forward coast re-fills (maybe_backward_recovery).

The canon demodulator change touched none of these.

5.2 Threshold-SNR comparison — turbo vs legacy (channel simulator)

Methodology. Per mode, a clean burst of a whole number of closed superframes (computed by frame::data_cw_per_superframe) is generated at repair = 0 (every codeword counts — RaptorQ disabled), then passed through study/nbfm_channel_sim.py at increasing noise. The metric is raw data codewords lost = (emitted n_total) − (unique LDPC-converged data codewords), measured for the turbo canon demod (turbo_sim rxreal) and the legacy rx_v2 batch (wav_replay_diag), on the same noisy WAV.

Noise knob. The sweep uses --audio-noise (post-demodulation AWGN — what the decoder's symbols actually see). The pre-demod --if-noise knob is not the right one here: the FM limiter suppresses IF amplitude noise (NBFM capture effect), so --if-noise up to 0.30 leaves the recovered MER essentially flat and never reaches the decode cliff. Drift is set to 0 to isolate the noise threshold; the channel model (pre/de-emphasis, FM hard-clip, band-limit) stays on.

Turbo noise tolerance (raw CW recovery vs post-demod noise). Each cell is data CWs recovered / emitted; the cliff is where recovery collapses. Constellation robustness orders exactly as expected — 64-APSK (HIGH++) breaks first, the QPSK low-rate modes (ULTRA/ROBUST) last.

Turbo vs legacy. On this synthetic channel the two decoders' raw decode thresholds coincide for HIGH / HIGH+ / ULTRA / ROBUST (both decode fully up to the same noise and fail past it) — the turbo path's real advantage is in equaliser quality (batch-level MER) and recovering marginal codewords on real channels, as shown by the byte-exact OTA captures (§5.1, where the per-symbol σ² recovered the last deep-fade CW that the old soft path lost). The legacy batch failed HIGH++ at every noise level through the sim (including clean) whereas the turbo path recovered it cleanly up to 0.05 — to be confirmed (a likely wav_replay_diag grace/gate artifact for the heavy 64-APSK batch decode).
Caveats on the legacy column. The legacy harness (wav_replay_diag) reports the worker's cumulative blocks_converged, which over-counts (2–3× n_total when it decodes) and reads 0 when it fails — so it yields a binary decode/fail signal, not a graded CW-loss curve. A clean graded turbo-vs-legacy CW-loss comparison needs the harness to count unique converged data ESIs (e.g. via the worker's converged_bitmap). MEGA (FTN, already flagged experimental and excluded from auto-detect) is set aside: it adds little over HIGH and complicates the turbo path, so it is not characterised here. Its clean byte-exact turbo_sim rx still passes; it is simply out of scope for the turbo effort for now.

Methodology details: 2 closed superframes per mode, repair=0; nbfm_channel_sim.py --if-noise 0 --drift-ppm 0 --audio-noise N; turbo via turbo_sim rxreal (uniqueDataESI), legacy via wav_replay_diag.

7. Open items

  • OTA / time-varying validation (review nits): the in-place live-tap adaptation could couple temporally on a fading channel (A/B vs snapshot-restore on a low-SNR capture); the DD-PLL now runs on APSK whereas track_segment ran it QPSK-only (A/B V3_NO_TURBO_PLL); measure per-segment cost on the Pi 4.
  • Deferred recovery levers (literature-grounded): for a clean-channel LDPC error-floor / trapping set — Informed Dynamic Scheduling / Residual BP, or BP+OSD (Fossorier); for a frequency-selective fade — a soft-DFE (Lopes–Barry) or MMSE-SISO turbo equalizer (Tüchler); BICM-ID a-priori demapping is labelling-gated (≈0 gain on our Gray / DVB-S2 APSK unless a non-Gray, non-interoperable labelling is adopted).
  • Modem auto-selection for the turbo path (read profile_index from the bootstrap marker, as rx_v2 already does).
